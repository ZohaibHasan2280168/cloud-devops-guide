# 07 — Amazon ECR Container Registry & Image Lifecycle

Amazon Elastic Container Registry (ECR) is a fully managed container registry that offers high-performance hosting, vulnerability scanning, and IAM-based access control for Docker and OCI images.

---

## 1. Why Amazon ECR vs Docker Hub?

1. **Native IAM Authentication:** EKS worker nodes and EC2 instances authenticate using attached IAM roles without storing hardcoded static credentials.
2. **Automated Vulnerability Scanning:** ECR scans container images for CVE security vulnerabilities on push.
3. **Internal VPC Speed & Low Egress Cost:** Pulling images into EKS within the same AWS region incurs zero data egress fees and maximizes pull speeds.

---

## 2. ECR Repository Creation via AWS CLI

```bash
# 💻 [Local Laptop Terminal]
ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
REGION="us-east-1"

# 1. Create ECR repository for Backend microservice with scan-on-push enabled
aws ecr create-repository \
  --repository-name smartdoc-backend \
  --image-scanning-configuration scanOnPush=true \
  --region $REGION

# 2. Create ECR repository for Frontend microservice
aws ecr create-repository \
  --repository-name smartdoc-frontend \
  --image-scanning-configuration scanOnPush=true \
  --region $REGION

echo "ECR Repositories created in $REGION under account $ACCOUNT_ID"
```

---

## 3. Docker Authentication & Image Push Workflow

Docker requires a temporary authentication token generated by the AWS CLI (valid for 12 hours):

```bash
# 💻 [Local Laptop Terminal] or ☁️ [Ubuntu EC2 Terminal]

# 1. Authenticate Docker CLI to your private ECR registry
aws ecr get-login-password --region $REGION | \
  docker login --username AWS --password-stdin $ACCOUNT_ID.dkr.ecr.$REGION.amazonaws.com

# 2. Build local Docker image
docker build -t smartdoc-frontend:latest ./frontend

# 3. Tag image with the specific Git Commit SHA (Immutable production artifact)
GIT_SHA=$(git rev-parse --short HEAD)
REGISTRY_URL="$ACCOUNT_ID.dkr.ecr.$REGION.amazonaws.com/smartdoc-frontend"

docker tag smartdoc-frontend:latest "$REGISTRY_URL:sha-$GIT_SHA"
docker tag smartdoc-frontend:latest "$REGISTRY_URL:latest"

# 4. Push both tags to Amazon ECR
docker push "$REGISTRY_URL:sha-$GIT_SHA"
docker push "$REGISTRY_URL:latest"

echo "Pushed image: $REGISTRY_URL:sha-$GIT_SHA"
```

## 4. Cost Optimization: ECR Lifecycle Policy

Untagged intermediate build images consume storage. Apply an **ECR Lifecycle Policy** to retain only the last 10 images and expire untagged images after 1 day:

```bash
# 💻 [Local Laptop Terminal]
cat <<EOF > ecr-lifecycle-policy.json
{
  "rules": [
    {
      "rulePriority": 1,
      "description": "Expire untagged images older than 1 day",
      "selection": {
        "tagStatus": "untagged",
        "countType": "sinceImagePushed",
        "countUnit": "days",
        "countNumber": 1
      },
      "action": {
        "type": "expire"
      }
    },
    {
      "rulePriority": 2,
      "description": "Keep only the last 10 production images",
      "selection": {
        "tagStatus": "any",
        "countType": "imageCountMoreThan",
        "countNumber": 10
      },
      "action": {
        "type": "expire"
      }
    }
  ]
}
EOF

# Apply policy to backend repository
aws ecr put-lifecycle-policy \
  --repository-name smartdoc-backend \
  --lifecycle-policy-text file://ecr-lifecycle-policy.json

# Apply policy to frontend repository
aws ecr put-lifecycle-policy \
  --repository-name smartdoc-frontend \
  --lifecycle-policy-text file://ecr-lifecycle-policy.json
```

## 5. Inspection & Image Deletion Commands

```bash
# 💻 [Local Laptop Terminal]
# List all repositories
aws ecr describe-repositories --output table

# List all image tags in a repository
aws ecr list-images --repository-name smartdoc-frontend --output table

# Delete an entire ECR repository and its images
aws ecr delete-repository --repository-name smartdoc-frontend --force
```
